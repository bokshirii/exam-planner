# Exam Planner

한국어 시험 대비 학습 플래너 MVP. React + TypeScript + Vite + Tailwind CSS + Lucide, Node.js + Express, Zod, Vitest를 사용합니다. 외부 인증·DB·결제·구독 없이 자신의 컴퓨터에서 실행합니다. 실제 데이터는 브라우저 LocalStorage에 저장하며, 처음에는 빈 상태입니다.

## 로컬 실행

Node.js 22.12 이상(검증 환경 Node 24), npm이 필요합니다.

```bash
npm ci
npm run dev
```

터미널의 Vite 주소(기본 http://localhost:5173)를 엽니다. 한 명령으로 프론트엔드와 API(127.0.0.1:3001)를 시작하고 Ctrl+C로 종료합니다. **환경 변수 없이 바로 사용할 수 있습니다.** 패키지 최초 설치와 선택적 Gemini 호출에만 인터넷이 필요합니다. 글꼴과 아이콘은 외부 CDN에 의존하지 않습니다.

```bash
npm test
npm run build
npm start
```

빌드 후 `npm start`를 실행하면 http://127.0.0.1:3001 에서 같은 앱을 사용할 수 있습니다. dev 주소와 start 주소는 다른 브라우저 저장 공간을 사용하므로 전환하려면 설정에서 JSON 백업·복원을 이용하세요.

## Gemini 설정 (선택)

1. `.env.example`을 프로젝트 루트의 `.env`로 복사합니다.
2. [Google AI Studio](https://aistudio.google.com/api-keys)에서 **결제를 연결하지 않은 Free 프로젝트**의 키를 발급해 `GEMINI_API_KEY`에 설정합니다. 결제 설정이나 플랜 업그레이드는 필요하지 않습니다.
3. 해당 프로젝트가 무료 티어임을 확인한 경우에만 `GEMINI_FREE_TIER_CONFIRMED=true`로 바꾸고 서버를 다시 실행합니다. 기본값 false에서는 외부 요청을 보내지 않습니다.

```dotenv
GEMINI_API_KEY=본인의_무료_프로젝트_키
GEMINI_FREE_TIER_CONFIRMED=true
PORT=3001
```

2026-11-17 확인한 [공식 요금표](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash-lite)에서 Standard 텍스트 입력·출력이 무료인 `gemini-2.5-flash-lite`를 선택했습니다. 모델 이름은 서버 코드에 고정되어 있으며 클라이언트에서 변경할 수 없습니다. OpenAI, 유료 전용 모델, 검색 grounding, 명시적 컨텍스트 캐싱, Batch, 기타 유료 도구를 호출하지 않습니다. 모델의 지원·무료 제공 정책은 Google이 변경할 수 있으므로 설정 전에 공식 표를 확인하세요. 사용할 수 없게 되면 규칙 분석으로 계속 사용할 수 있습니다.

무료/유료 여부는 Google 프로젝트에 귀속됩니다. 일반 API 키 문자열만으로 서버가 프로젝트 결제 상태를 판별할 수는 없습니다. 이 앱의 확인 변수와 호출 제한이 Google의 결제 설정을 변경하거나 과금을 차단하는 기능은 아닙니다. **결제를 연결하지 않은 키만 사용하거나 키 없이 실행하세요.** 무료 티어의 입력이 제품 개선에 사용될 수 있다는 Google 정책은 공식 요금표와 약관을 참고하세요.

키는 dotenv를 읽는 백엔드에서만 사용하고 `VITE_` 환경 변수나 프론트 번들에 넣지 않습니다. `.env`는 gitignore 대상입니다. 서버는 loopback에 바인딩되고 외부 Origin의 API 요청을 거부합니다. 원격 배포용 서버는 아닙니다.

### 호출과 오류 처리

- 사용자가 등록 화면에서 **AI로 학습 항목 분석**을 누를 때만 요청합니다. 일정 생성·재계획·완료 체크는 API를 호출하지 않습니다.
- 성공한 분석은 정규화한 입력의 SHA-256 키로 서버 메모리에 최대 200개 저장합니다. 같은 입력을 다시 분석하면 재사용하고 동시 중복 요청도 하나로 합칩니다. 캐시는 서버 재시작 시 초기화됩니다. Google의 유료 캐싱 기능을 사용하지 않습니다.
- 프로세스당 최근 24시간 최대 20회 요청, 15초 제한, 자동 재시도 없음. 429는 한 시간 동안 추가 호출을 막고 규칙 분석으로 전환합니다. 이 앱 제한은 Google 공식 무료 쿼터와 별개이며 서버 재시작 시 초기화됩니다.
- 키 없음, 무료 프로젝트 확인 없음, 서버 연결 실패, API 오류, 한도 초과, 잘못된 JSON·선행 관계는 규칙 기반으로 전환하고 안내합니다.
- Zod로 응답 항목·분량·종류·시간·이전 항목 의존성을 검증합니다. AI 결과는 검토 후에만 저장합니다.
- 규칙 분석은 줄·쉼표 분리, Chapter/문제셋 범위와 횟수를 확장합니다. 교재의 내용을 만들어내지 않고 시간은 추정값으로 표시합니다.

## 사용 방법

1. 새 시험 등록에서 이름·시험일·자연어 공부 범위를 입력합니다. 색상·중요도·메모·복습 기간도 설정할 수 있습니다.
2. 분석 버튼을 누르고 항목 이름·시간·유형·중요도·포함 여부·선행 항목을 검토합니다. 항목 추가·삭제도 가능합니다. 선행 항목은 이전 항목만 선택하고, 다중 선택은 Ctrl/Cmd를 사용합니다.
3. 학습 계획을 생성하면 날짜별 미리보기·총 공부량·가용 시간·미배정 항목을 표시합니다. 확인한 뒤에만 저장합니다.
4. 대시보드 또는 월간 캘린더에서 날짜를 선택하고 세션별 완료를 체크합니다. 연필 버튼으로 시간·날짜를 수정하고 자물쇠로 고정합니다.
5. 시간 설정에서 요일별 분량, 평일/주말 일괄 입력, 특정 날짜 예외, 쉬는 날을 설정합니다. 재계획 버튼으로 변경 내용을 확인하고 반영합니다.
6. 내 시험에서 시험 정보와 학습 항목 이름·전체 예상 시간을 수정하거나 삭제할 수 있습니다. 완료 항목은 기록 보호를 위해 삭제가 제한됩니다.
7. 설정에서 JSON 백업과 검증된 백업 복원을 사용할 수 있습니다.

직접 추가한 학습 항목은 첫 시험에 추가됩니다. 내 시험에서 항목 이름과 전체 시간을 편집할 수 있습니다. 완료·고정 기록이 있는 시험의 범위 전체 재분석은 금지하며 시험 정보 수정과 개별 항목 추가·편집을 사용합니다. 완료 세션의 날짜·시간은 편집하지 않고, 완료 취소는 가능합니다.

## 일정 알고리즘

`src/core.ts`의 순수 TypeScript `schedule(state, start)`가 AI와 독립적으로 동작합니다.

- Asia/Seoul 기준 오늘을 구하고 YYYY-MM-DD를 사용합니다. 날짜 덧셈은 UTC 정오 기반으로 처리해 시간대 변환에 의한 하루 이동을 방지합니다.
- 오늘부터 시험 전날까지 최대 10년 범위를 배정합니다. 오늘/지난 시험은 미배정으로 남습니다.
- 모든 시험이 요일·날짜 예외·제외일의 가용 시간을 공유합니다. 완료·고정 세션부터 시간을 차감합니다.
- 마감일, 동일 마감의 남은 공부량/남은 일수, 시험 중요도, 항목 중요도, 학습 순서, ID로 안정적으로 정렬합니다.
- 한 세션은 최대 60분으로 분할하며 남은 분량도 배정합니다. 의존 항목의 전체 분량이 앞서 배정되어야 후속 항목을 배정합니다. 같은 날에는 목록 순서가 학습 순서입니다.
- 복습 항목은 설정한 마지막 N일에 배정합니다. 0일은 별도 복습 기간을 예약하지 않습니다. 문제 풀이는 선행 조건·학습 순서에 따라 개념 뒤에 배치됩니다. 강제로 마지막 며칠에 집중시키는 별도 최적화는 없습니다.
- 미완료 과거 세션과 미래 미고정 세션을 다시 계산하고, 완료·고정 세션은 객체 내용과 ID를 그대로 보존합니다. 생성 ID는 task/date/순번 기반입니다.
- 고정된 미래 선행 세션보다 앞서 후속 항목을 배치하지 않습니다. 잘못된 의존 관계·순환은 미배정으로 처리합니다.
- 이미 완료·고정된 양이 새 가용 시간을 초과하면 이동시키지 않고 경고합니다. 수정 시에는 일일 총량과 항목 전체 시간을 초과하지 못하게 검증합니다.
- 재계획 적용 전 날짜별 총 시간 전후, 보존/변경 세션 수, 새 배정 목록, 미배정 항목을 보여줍니다. 확인 전까지 원본 기록을 변경하지 않습니다.
- 진행률은 항목 전체 예상 시간 대비 완료 세션의 분 가중치이며 0분모는 0%입니다.

## 프로젝트 구조

```text
src/
  core.ts          데이터 모델, 날짜, 규칙 분석, 일정 알고리즘, 진행률
  storage.ts       Zod 검증, LocalStorage 저장소 (추후 DB 교체 경계)
  main.tsx         대시보드, 캘린더, 시험, 설정, 등록/재계획/수정 화면
  style.css        Tailwind와 반응형 UI
server/
  index.ts         Express API, 요청 검증, 로컬 Origin 제한, 정적 앱 제공
  analyze.ts       Gemini 서버 호출, 검증, 캐시, 한도·오류 fallback
scripts/dev.mjs    프론트·백엔드 동시 실행과 종료
tests/             일정 11개, 분석 5개, 저장소/통합 흐름 3개
.env.example       선택적 서버 환경 변수
```

## 구현 범위와 제한

구현: 실제 시험 CRUD, 3단계 분석·검토·계획 확정, 항목 편집·추가·삭제, 요일/일자별 가용 시간, 다중 시험 공유 일정, 분할 세션별 완료·취소·이동·고정, 월간 캘린더, D-day와 진행률, 재계획 미리보기·확정, 미배정 경고, LocalStorage 복원, JSON 백업·복원, Gemini/규칙 분석 전환.

제외: 외부 DB·인증·소셜 로그인·결제·알림 서버, 백그라운드 자동 재계획, 계정/기기 간 동기화, 시간대 선택(현재 Asia/Seoul 고정), 드래그 캘린더 편집, 폼 기반의 복잡한 항목 편집과 전용 접근성 감사. 프론트 UI는 한 파일에 모은 MVP 구조입니다. 가용 시간 합계는 가장 늦은 시험 전날까지의 공통 자원이며 개별 시험의 실현 가능성은 미배정 목록으로 판단합니다.

## 검증

- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 통과.
- `npm test`: Vitest 19개 통과. 일정 분할, 공유 가용 시간, 미배정, 완료·고정 보존, 미래 고정 선행 조건, 순환·누락 의존성, 예외일, 지난 시험/내일/모두 완료, 날짜 경계·윤년, 규칙 분석, 키 미설정, 무료 확인 없음, 잘못된 AI JSON, 캐시, 429, 실제 등록→분석→계획→완료→저장/복원→재계획 흐름, 손상된 저장값과 잘못된 날짜를 검증합니다.
- 로컬 HTTP 확인: 상태 조회 200, 키 없는 분석 200(규칙 분석 6개 항목), 빈 입력 400, 외부 Origin 403, 프로덕션 앱 200.
- 실제 Google API는 키가 없어 호출하지 않았습니다. AI 정상 응답·오류는 mock으로 검증했습니다.
- 클라우드 미리보기의 포트 전달/릴레이 연결 실패로 브라우저 클릭·모바일 화면·새로고침 동작의 수동 E2E 검증은 완료하지 못했습니다. 저장/복원은 메모리 LocalStorage mock 통합 테스트로 검증했습니다.

데이터는 기기·브라우저·접속 주소에 종속됩니다. 저장 오류는 안내하고, 손상 데이터는 로드 시 자동 덮어쓰지 않습니다. 복원 또는 새 저장을 하기 전 필요하면 브라우저 개발 도구에서 기존 값을 별도 보관하세요.
